# API 中断与空白占位页修复

## 事故与原因

2026-09-07 晚间两个 worker 遇到模型请求超时和连接失败；协调日志出现 `Connection refused`。102556 留有 48 个占位页，15560 留有 65 个占位页；102910 的 183 页和 16000 的 77 页全部生成空白占位，但原流程仅校验页码和编译通过，仍错误发布。前两个文档则因为全部选中字段复核失败而退出。

## 处理规则

- 识别连接失败、超时、429 和服务端错误最多重试一次，随后停止共享请求队列并保留进度；401/403 直接暂停。异常日志只记录类型和状态码。
- 网络故障不生成或缓存新占位页，不通过升级模型继续请求失联网关。
- 已存在的识别失败占位缓存不作为命中，恢复后只补这些页；正常空白原页没有失败标记，不受影响。
- GPT-6 升级过程中断连同样暂停；记录为连接失败的旧升级尝试可在恢复后重试，已返回结果仍复用。
- 识别和优化阶段均检查占位标记，正式发布再次检查。任意识别失败占位页都阻止发布，既有正式结果不会被覆盖。
- 协调不可用时停止剩余复核请求，保留 TEX 原值并在字段 JSON 中记录待核对；可用 TEX 继续进入优化编译。
- 普通批处理检测到接口不可用时暂停后续文件；单 worker 顺序队列遇到任务失败也停止推进，剩余文件保持待执行。
- 监控不把占位缓存计为有效页，也不把占位 TEX 当作已发布；每日完成统计排除占位产物。

本次已将两份全空白 TEX 及其原记录备份到 `data/quarantine/2026-09-08-empty-publications`，移出正式目录，撤回日报中两条无效完成记录，共 260 页。保留失败请求日志供后续恢复时核算；缺失 usage 不视为零消耗。

## 恢复

使用新镜像和原工作目录续跑，不删除识别缓存、不改变 DPI 或模型提示词。流水线版本使旧整阶段完成记录失效，逐页有效缓存仍复用。接口健康探测返回鉴权响应只证明网络已连通，不证明付费模型调用成功；恢复后需核对实际模型响应和缓存增长。

## 验证

回归测试覆盖持续断连的有限请求数、鉴权与限流重试次数、缓存补跑、GPT-6 升级恢复、占位发布拦截、批处理暂停、协调保留原值、监控及日报排除无效结果。正常空白页允许发布，字段元数据缺失不作为占位页处理，分页差异继续保留为提示。
